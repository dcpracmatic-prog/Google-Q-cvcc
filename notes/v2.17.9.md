# v2.17.9 — El lote Montgomery rompía la fase: inversos directos

Fecha: 2026-11-18. Autor: DC PRACMATIC (a pedido de Arturo: "hazlo funcionar").

## El problema

El generador híbrido (`build_hybrid_bm.py`) NUNCA pasó la verificación
de fase: 510 intentos, 0 PASS. El `verify_small` con el gate de fase
v2.17.7 rechazaba sistemáticamente (3-5 errores de fase de 8 shots),
con sigma y registros intactos. La ablación v2.17.8 mostró que
batch=1 pasaba (0 errores) y batch>=2 fallaba: el defecto estaba en
el lote Montgomery, no en el camino por posición.

## La investigación (Exp A-I, sandbox, n=10, m=15, seed 12345, 8 shots)

Todos los experimentos están en `exp_fase_*.py` (entorno de trabajo,
no en el repo). Resultado de cada uno:

| Exp | Pregunta | Resultado |
|-----|----------|-----------|
| A | ¿Errores vs tamaño de lote? | batch=1: 0 errores. batch=2: 3, batch=3: 4, batch=4: 3, batch=8: 2. Cualquier lote >= 2 falla. Sigma 48/48 y registros 96/96 siempre intactos. |
| B | ¿Es la limpieza final del lote? | batch=4 SIN limpieza: mismos 3 errores. No es la limpieza. |
| C | ¿Son correctos los inversos derivados? | Exp C tenía un bug (usaba un registro liberado). Exp C2 (corregido): r_inv=1665 correcto, q[1]=3482 correcto, multiplicador aislado 3097*628=1665 correcto. |
| C3 | ¿Correctos en TODOS los shots? | 8 shots x 4 posiciones: 0/32 mismatches. Los valores derivados son correctos. |
| D | ¿Es `del_gf2_mul`? | Reemplazarlo por `_ixor_mul`: mismos 3 errores. No es. |
| E | ¿Es el multiplicador nativo? | Reemplazar `_ixor_mul` por Toom-3: mismos 3 errores (T baja 6630→3957, fase igual). No es el multiplicador. |
| F1 | ¿Es el inverso compartido? | Lote con inversos DIRECTOS por posición (sin derivar): mismos 3 errores. No es el inverso compartido. |
| F2 | Control: solo `_single_position` | 8/8, 0 errores. El bucle en sí no es el problema. |
| F3 | Singles + p + inverso compartido decorativos | 8/8, 0 errores. Los productos p y el inverso compartido (init+del) son inocentes. |
| F4 | F3 + derivaciones q decorativas (antes de las patadas) | 8/8, 0 errores. Las derivaciones q solas no corrompen. |
| G | Patadas diferidas con COPIAS de los inversos | Falla (batch=2: 5, batch=4: 2 errores). La copia no salva. |
| H | Single + copia CNOT del inverso antes de patear | Falla (4 errores). **La copia CNOT en sí rompe la fase.** |
| I | r_inv originales guardados, cadena fuera, patear | Falla (batch=2: 3, batch=4: 4). Montgomery no se salva. |

Conclusión medida: en kickmix 1.0.0, la fase DQI se corrompe cuando
las patadas ocurren con maquinaria Montgomery viva (F1), cuando se
usan copias CNOT de un inverso (H, G) o cuando intervienen las
multiplicaciones de la cadena q (I). La única configuración que pasa
es la de F4 / `_single_position`: inversos directos por posición,
sin maquinaria Montgomery en juego. Los valores son correctos en
todos los casos (C3); lo que se corrompe es la FASE, no el valor —
consistente con HMR sin arreglo de fase en la descomputación de
kickmix, dependiente del entrelazamiento y de los valores.

## La corrección

`hybrid_scan` usa SIEMPRE `_single_position` (inversos directos, uno
por posición). `montgomery_batch` se conserva en el archivo solo como
referencia, con su advertencia (NO usar para fase). El parámetro
`batch` queda sin efecto para el scan (se conserva por API y para el
conteo informativo de lotes). `diagnose_phase_ablation` ahora es una
comprobación de regresión (todos los lotes deben salir limpios).

## Números medidos (sandbox, venv Python 3.12, kickmix 1.0.0)

`verify_small` (n=10, m=15, seed 12345, 8 shots): batch 1, 2, 3, 4,
8, 17 → **8/8 fase, 0 errores, valid=True**. Semillas 1, 999, 2026 →
8/8. Ablación: `all_paths_phase_clean=True`.

Circuito completo (n=10, m=15, batch=4, nslot=6): **Q=1067** (antes
1139, -72), **T=29,481** (antes 28,587, +894). S=3.9983e10 (el mejor
anterior de batch=1; ahora todos los batch empatan ahí).

Escala completa (n=70, m=4095, batch=17, nslot=36): **Q=6,407**
(antes 6,791), **T=2,283,981** (antes 1,900,947), **S est. = 1.12e14**
(R=1.1912605). El S Montgomery con Toom-4 (7.99e13) era FICTICIO:
ese circuito nunca pasó la verificación de fase (0 PASS en 510
intentos). El S correcto es el de inversos directos: 4.6x peor que
el baseline (2.44e13), 5.6x peor que el ensamble (1.998e13). La
fase correcta vale más que un S ficticio.
