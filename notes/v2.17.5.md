# v2.17.5 — No repetición + LLM usa el código del repo + 3 tareas (2026-11-14)

Pedido de Arturo: penalización de no repetición de semillas, opción
de que el LLM use las estructuras .py del repo mismo, y ejecutar
las 3 tareas ~1 hora o 25 circuitos diferentes c/u.

## Lo que se supo de la v4 en Kaggle (kernel 145011974 v4)

La v4 SÍ completó `run_autonomous` (14 semillas, 12 llamadas LLM,
0 fallbacks). La mejor semilla fue la #1: batch=4, nslot=16,
toom3=true, Q=2,919, T=186,117, **S=1.8891e12, 19.1% mejor que la
primera (2.3366e12)**. El "error" del kernel era solo el reporte
de la celda 3 (KeyError: las semillas inválidas #11 y #12, con
batch=1 que el generador rechaza, no tienen 'qubits').

Dos hallazgos que motivan esta versión:
- **La semilla #13 repitió la #1 exactamente** (batch=4, nslot=16,
  toom3=true). El LLM volvió a proponer la mejor. Sin penalización,
  se gasta una llamada y una medición en un circuito ya conocido.
- Las semillas #11/#12 fallaron por batch=1 (TypeError de kickmix);
  el try/except de v2.17.2 las registró y la corrida siguió (bien),
  pero el reporte no las aguantaba (se arregla en el Notebook v5).

## Qué se cambió

- **`auto_mvp/autonomous.py`** — `_NoRepetir` (penalización de no
  repetición): un `seen` global con los knobs (batch, nslot, toom3),
  los hashes de código y los nslots ya probados. El prompt del
  estratega lleva los knobs ya probados (últimos 12) para que no
  los repita. Si el LLM propone uno repetido, se cuenta
  `repetidas` y NO se mide (se busca otro con
  `_default_delta_no_repetido`). El resultado trae `repetidas` y
  `unicas` (circuitos distintos medidos). La param nueva también
  registra el knob completo (antes solo el nslot: `unicas` quedaba
  corto).
- **Tarea código-repo**: `_prompt_codigo_repo` le da al LLM las
  estructuras .py del repo (build_hybrid_bm_circuit, verify_small,
  toom3/FIELD12/FIELD4/gf4_*, dqi_S/R_DQI, _DEFAULT_BATCH) y le
  pide `novel_seed(n, m)` que las IMPORTE y las USE para calcular
  los knobs. Se valida (guarda de imports, entry="novel_seed"), se
  ejecuta y se mide. El prompt advierte usar True/False de Python
  (no true/false de JSON: un falso que devolvía `false` rompía la
  ejecución con NameError).
- **`run_tres_tareas`**: las 3 tareas, cada una 1 hora
  (time_budget_seconds=3600) o 25 circuitos DISTINTOS
  (n_objetivo=25), lo que llegue primero, con el `seen`
  compartido: (1) knobs (run_autonomous, sin param nueva suelta),
  (2) codigo_repo (novel_seed en bucle), (3) param_nueva
  (novel_nslot en bucle, nslot distinto). Guarda
  `tres_tareas.json` + `semillas.json` + `VEREDICTO.json`.
  CLI: `python -m auto_mvp.autonomous --tres-tareas`.
- **`tests/test_autonomous.py`** — +3 tests (10/10): no-repetición
  (el falso propone siempre lo mismo: repetidas>=2, todas las
  semillas distintas), código-repo (novel_seed importa R_DQI del
  repo y se mide), tres-tareas (las 3 corren a escala chica, sin
  repetir ninguna semilla medida).
