# v2.17.0 — Generación autónoma de semillas + el LLM ya es local (2026-11-14)

Dos pedidos de Arturo (2026-11-14) en la misma versión:

1. El Notebook tenía muchas celdas muy amplias; eso debería
   funcionar DESDE el repositorio y el Notebook solo ser un código
   de ejecución, automático: hace todas las instalaciones y las
   importaciones, empieza a trabajar y entrega circuitos, y si los
   mejora, ideal. La lógica vive en el repo, no en el Notebook.
2. Quitar Gemini/Groq (API, llave) y usar Qwen2.5-Coder-1.5B-
   Instruct (GGUF Q4_K_M, llama-cpp-python, temp 0.7-0.8). El LLM
   no debe pedir ninguna API para funcionar.

## Qué se añadió

- **`auto_mvp/autonomous.py`** — el ejecutor autónomo del repo.
  - `LocalLLM`: el LLM local Qwen2.5-Coder-1.5B-Instruct (GGUF
    Q4_K_M, llama-cpp-python, temp 0.7, rango de Arturo 0.7-0.8).
    Sin Gemini/Groq, sin llave. `llama_cpp` se importa perezoso
    (dentro de `__init__`): el módulo se importa aunque
    llama-cpp-python no esté instalado; el error sale solo al
    construir el modelo. Métodos `complete`, `complete_json`
    (misma interfaz que `auto_mvp.llm.complete_json`) y
    `complete_code` (primer bloque ```python).
  - `validate_code`: guarda de imports para el código que propone
    el modelo (solo math/typing/auto_mvp/kickmix; nada de os/sys/
    subprocess/eval/exec; debe definir la función pedida con ≥1
    parámetro). Nada que falle la guarda se ejecuta.
  - `setup_kaggle`: encuentra la competencia en /kaggle/input
    (los montajes vienen ANIDADOS) y deja `kickmix` con Circuit
    (el kickmix.so del dataset o pip force-reinstall kickmix==1.0.0).
  - `run_autonomous`: el bucle autónomo. Sin base, sin baseline,
    sin puntuación máxima. La primera semilla se genera y se mide
    (es la primera, no una referencia) con el generador del repo
    (`build_hybrid_bm_circuit`, `_measure_knobs` de llm_auto_dqi:
    Q/T/S + `verify_small`). Cada semilla nueva la propone el LLM
    (una parametrización: batch, nslot, toom3) y solo sobrevive la
    que baja el S respecto a la mejor hasta ahora (mejora interna,
    autónoma). Sin modelo (o con JSON malo), sigue con los knobs
    por defecto. Al final, el LLM propone una parametrización nueva
    (`novel_nslot`, una función chica, no un circuito entero) y se
    mide una semilla con ella; si falla, se registra y se sigue.
    Guarda `semillas.json` (las semillas + sus parametrizaciones),
    `param_nueva.json` y `VEREDICTO.json` en `output_dir`.
  - CLI: `python -m auto_mvp.autonomous --model <gguf> --n 30
    --m 255 --n-semillas 12 --output-dir .` (sin --model, corre
    sin modelo, con knobs por defecto).

## Alcance honesto

- La lógica de generación autónoma vive en el repo y el Notebook
  de Kaggle es delgado (2 celdas de código: instalar + ejecutar
  `run_autonomous`). La instalación del LLM (pip install
  llama-cpp-python + descarga del GGUF Q4_K_M + SHA256) sigue
  haciéndose EN KAGGLE, en el Notebook: el modelo de 1 GB NO va
  en el repo.
- El LLM real (Qwen2.5-Coder local en Kaggle) ya se probó en el
  Notebook v5: 3 llamadas, 0 fallbacks, propuestas válidas. El
  circuito nuevo entero falló (el modelo escribió un esqueleto
  vacío); por eso aquí se le pide una función chica (`novel_nslot`),
  que es lo que el modelo de 1.5B sí puede escribir.
- `run_autonomous` no busca una puntuación máxima ni compara con
  un baseline: la mejora es interna (cada semilla vs la mejor
  hasta ahora). El S que ordena las semillas usa R=1.1912605
  (medido en el DQI de referencia), igual que el corredor DQI.
- El LLM ya no pide API ni llave: corre en la máquina. Pero es
  un modelo chico (1.5B); sus propuestas no siempre mejoran en
  pocas rondas. Darle más propuestas (o el Q8_0, ~1.6 GB, más
  preciso) es lo que le daría más aciertos.
- La suite completa no se re-corrió entera en este cambio (solo
  los 17 tests de los módulos tocados).
