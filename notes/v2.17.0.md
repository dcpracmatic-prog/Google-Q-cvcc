# v2.17.0 — El LLM ya es local: Qwen2.5-Coder, sin API, sin llave (2026-11-14)

Pedido de Arturo (2026-11-14): quitar Gemini/Groq (API, llave) y
usar Qwen2.5-Coder-1.5B-Instruct (GGUF Q4_K_M, llama-cpp-python,
temp 0.7-0.8). El LLM no debe pedir ninguna API para funcionar.

## Qué cambió

- **`auto_mvp/llm.py` reescrito (v2.17):** el cliente ya no es
  una API. Es el modelo LOCAL Qwen2.5-Coder-1.5B-Instruct, GGUF
  Q4_K_M, cargado con llama-cpp-python, temperatura 0.7 (rango de
  Arturo: 0.7-0.8). Sin llave, sin red, sin URL de API. El modelo
  (GGUF ~1.0 GB) NO va en el repo: se baja de HuggingFace la
  primera vez (`ensure_model`, verifica SHA256
  `cc324af0...bb046`) o se pone en `LLM_MODEL_PATH`. En Kaggle lo
  baja el Notebook a `/kaggle/working/`; en sandbox, a
  `~/workspace/models/`. La interfaz no cambia: `complete()` y
  `complete_json()` devuelven lo mismo que antes, así que los
  corredores no se tocan más que para quitar `provider`.
  `LLMError` gana el flag `no_model=True` (falta el GGUF o
  llama-cpp-python): el corredor cae a los knobs por defecto.
- **`auto_mvp/llm_auto.py` y `auto_mvp/llm_auto_dqi.py`:**
  quitado el parámetro `provider` y el flag `--provider` de los
  CLI. El cliente real es ahora `complete_json(prompt)` (local).
  Los docstrings ya no hablan de llave.
- **`tests/test_llm_v220.py`:** los tests de la API (sin llave,
  429, urlopen) se reemplazaron por tests del cliente local
  (sin modelo -> `LLMError(no_model=True)`; `complete_json`
  extrae el JSON de un texto simulado del modelo local; el
  corredor sin modelo cae a sa_windows).

## Medido (verificado, sandbox)

- `llama-cpp-python 0.3.36` instalado (TMPDIR en el home: el
  `/tmp` de 512 MB no alcanza para compilarlo).
- GGUF bajado a `~/workspace/models/`: 1,117,320,768 bytes,
  SHA256 coincide.
- Cliente local REAL (sin ninguna llave en el entorno):
  `complete_json` devolvió un JSON válido con 4 deltas
  (batch 4/8/17/36, nslot 6, toom3 False/True).
- Corredor DQI con el modelo local REAL (sin llave): 2 llamadas,
  0 fallbacks, 6 propuestas, 0 inválidas. El mejor quedó en la
  base (S=4.21e10, batch=4, nslot=6, toom3=False): el modelo
  propuso deltas válidos pero en esas 6 no dio con el toom3 que
  mejora. El corredor midió y no empeoró (eso es lo que hace el
  verificador). Con cliente falso, el mismo corredor SÍ guarda
  el toom3 (S=3.42e10), así que el bucle funciona; el modelo
  chico (1.5B) propone, y solo lo que mide mejor sobrevive.
- Tests: 11/11 (test_llm_v220 + test_llm_dqi).

## Alcance honesto

- El LLM ya no pide API ni llave: corre en la máquina. Pero es
  un modelo chico (1.5B); sus propuestas no siempre mejoran en
  pocas rondas. Darle más propuestas (o el Q8_0, ~1.6 GB, más
  preciso) es lo que le daría más aciertos.
- El GGUF (~1 GB) no va en el repo ni se sube a GitHub: vive en
  `~/workspace/models/` (sandbox) y lo baja el Notebook en Kaggle.
- La suite completa no se re-corrió entera en este cambio (solo
  los 11 tests de los módulos tocados).
