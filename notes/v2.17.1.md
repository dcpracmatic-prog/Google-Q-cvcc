# v2.17.1 — El import de autonomous ya no necesita kickmix (2026-11-14)

Corrección del bug que tumbó el Notebook v2 en Kaggle (kernel
145011974 v2, error a los ~8 min, sin mensaje de Kaggle).

## Causa (reproducida en sandbox)

En Kaggle `import kickmix` trae un paquete VACÍO (sin `Circuit`,
sin `GF2Field`) hasta que se carga el `kickmix.so` del dataset o
se reinstala por pip. `auto_mvp/circuits/generators/build_hybrid_bm.py`
crea `FIELD = km.GF2Field(DEGREE)` al importarse (línea 103) y
`toom3.py` igual (`FIELD12`, `FIELD4`). `auto_mvp/autonomous.py`
(v2.17.0) importaba `build_hybrid_bm` y `llm_auto_dqi` al cargarse,
así que el `from auto_mvp.autonomous import QWEN_GGUF_URL` del
Notebook v2 fallaba con `AttributeError: module 'kickmix' has no
attribute 'GF2Field'` ANTES de bajar el GGUF (la salida del kernel
solo traía el `repo/` clonado, sin GGUF ni `semillas.json`). El
Notebook v1 había fallado antes (~2 min) por otra causa (probable
competencia no encontrada, que también se endurece aquí).

Reproducido en sandbox con un `kickmix` vacío en `sys.modules`:
`import autonomous` fallaba con ese AttributeError. Con la
corrección, el mismo subproceso importa bien.

## Qué se cambió

- **`auto_mvp/autonomous.py`** — import perezoso: `llm_auto_dqi`
  (`R_DQI`, `_measure_knobs`, `_parse_deltas`) se importa DENTRO
  de `run_autonomous`, después de `setup_kaggle()`. Los imports
  directos de `build_hybrid_bm_circuit` / `verify_small` se
  quitaron (no se usaban: todo pasa por `_measure_knobs`).
  `_prompt_autonomous` ahora recibe `r_dqi` como parámetro.
- **`setup_kaggle`** — ya no exige encontrar la competencia: si
  no está montada, salta el `.so` y va directo a pip install
  kickmix==1.0.0. Generar semillas no necesita el dataset (solo
  kickmix); solo se falla si kickmix sigue sin `Circuit` tras
  todos los intentos. Devuelve `Path | None`.
- **`tests/test_autonomous.py`** — +1 test de regresión
  (`test_import_autonomous_sin_kickmix`): subproceso limpio con
  un `kickmix` vacío; importar `autonomous` debe funcionar.
- `auto_mvp/__init__.py` + `pyproject.toml`: versión 2.17.1.

## Medido (verificado, sandbox)

- Subproceso con kickmix vacío: v2.17.0 fallaba (AttributeError
  GF2Field); v2.17.1 importa bien (`import autonomous OK sin
  kickmix`).
- Tests dirigidos: 20/20 (autonomous 6 + versión 1 + llm_dqi 4 +
  hybrid_bm 5 + smoke 4). La suite completa no se re-corrió entera
  (la máquina estaba cargada por el SA del coordinador invsqrt);
  el cambio solo mueve imports y endurece `setup_kaggle`.

## Alcance honesto

- El Notebook v3 (delgado) usa este `autonomous.py`: importa el
  módulo (seguro sin kickmix), llama `setup_kaggle()` y luego
  `run_autonomous`. Si el LLM local falla (pip/GGUF), el Notebook
  sigue con `llm=None` y entrega semillas con knobs por defecto:
  la corrida ya no depende del LLM para producir salida.
- El Notebook v1 falló por otra causa (probable competencia no
  encontrada a los ~2 min); `setup_kaggle` ya no falla por eso.
  Si v3 vuelve a fallar, el Notebook escribe un log de progreso
  en `/kaggle/working/log.txt` para ver dónde se quedó.
