# v2.17.22 — Arreglo del verificador oficial en Kaggle (resolver)

## El bug (medido en Kaggle, kernel 146312858 v5, 2026-11-21)

La demo 2 del notebook de la Skill/Tool (pantalla oficial del fixture
invsqrt) moría en `In [3]` con `ModuleNotFoundError`:

```
auto_mvp/vqcc/verify.py, _kaggle_circuit_verifier
  from .kaggle_init import detect_environment
```

`kaggle_init` vive en `auto_mvp` (paquete padre), no en `auto_mvp.vqcc`:
el import relativo `.` buscaba `auto_mvp/vqcc/kaggle_init.py`, que no
existe. En sandbox nunca se ejercía esta rama: el venv toma el camino
local (`competition-verifiers` + venv python), así que los 6 tests de
`test_skill_chain.py` pasaban y el bug solo apareció en Kaggle.

## El segundo problema (misma corrida)

`KAGGLE_COMPETITION` estaba fijo en
`/kaggle/input/competitions/google-verifiable-quantum-circuit-compilation`,
pero este kernel monta el dataset en
`/kaggle/input/google-verifiable-quantum-circuit-compilation` (sin
`competitions/`): se creó sin el campo `id` y Kaggle lo registró como
dataset, no como competition. Con solo el import arreglado, el resolver
habría devuelto None (script no encontrado) -> VETO_SIN_VERIFICADOR.

## El arreglo

- `auto_mvp/vqcc/verify.py`:
  - `from .kaggle_init` -> `from ..kaggle_init`.
  - `_kaggle_competition_dir()`: resuelve el dir del dataset probando
    primero `competitions/<slug>` y luego `/kaggle/input/<slug>`.
  - `_kaggle_circuit_verifier` usa ese dir para el script y para el
    `kickmix.so` (PYTHONPATH).
- `tests/test_skill_chain.py`: nuevo test
  `test_kaggle_verifier_resolver_import_y_rutas` (7 tests en el archivo)
  que reproduce la regresión en sandbox con un dir de dataset falso y
  `detect_environment` parcheado a "kaggle".
- Versión 2.17.22 (`auto_mvp/__init__.py`, `pyproject.toml`).

## Medición

- Sandbox (venv): `tests/test_skill_chain.py` **7/7 PASSED** (1.22 s),
  incluido el test de regresión nuevo.
- Kaggle v5 (antes del arreglo): setup OK, **demo 1 OK** (cadena en una
  llamada, PASS_LOCAL, túnel chien T 1,511,522 -> 1,315,731,
  delta -195,791), fixture sha d0227f3c OK, demo 2 falló con el
  ModuleNotFoundError de arriba. La v6 (con este arreglo) es la que
  debe medir la pantalla oficial y el dominio completo.
